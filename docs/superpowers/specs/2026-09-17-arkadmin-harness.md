# ArkAdmin 插件 Harness 规格 — 终态与路线图

> 日期：2026-09-17 ｜ 来源：grilling 三轮访谈（用户逐项拍板） ｜ 状态：**已确认，作为 M6+ 计划依据**
> 上位文档：`2026-09-14-arkadmin-design.md`（架构基线不变，本文件收窄「一切皆插件」的边界并排定打磨路线）

## 1. 终态陈述

框架核心是**薄 harness**：认证、RBAC、菜单、插件机制本身、响应信封、素材基建——到此为止。其余能力一律以
**插件形态**存在，其中随仓库捆绑的叫**系统插件**（与业务插件同机制装卸，无特权）。目标不是「功能多」，
而是「核心够薄、机制完整、扩展点先行」；插件机制自身的完整度（扩展点、管理界面、升级路径）是终态的主体。

打磨优先级：**正确性 → 交互 → 视觉**（每个里程碑内测试先行；视觉在业务形态稳定后一轮做完）。
部署搁置：打磨满意后一次性推自有 VPS 单机全栈；期间用 git tag 标记稳定点。

## 2. 架构分层（切割线，Q1-A 定案）

| 层 | 内容 |
|---|---|
| **核心（harness 骨架）** | 认证（Sanctum+管理员）、RBAC（spatie）、菜单、插件机制（引导/生命周期/CLI/前端同步/编译缓存）、响应信封、**素材基建**（attachments 表/上传 API/素材库页面——被 CMS 强依赖，插件化收益低，留核心并留 backlog）、**settings 存取基建**（见 §4，被消费的基建在核心） |
| **系统插件**（随仓库捆绑、无特权、可卸载可重装） | ① `settings`：schema 声明 + 设置管理页；② `op_logs`：监听框架埋点事件、存储与查询、贡献统计卡片 |
| **核心（M6 实施期修正）** | 仪表盘 widget 消费壳留核心（`dashboard/index.vue`）：壳无独立业务数据，做成插件反而破坏「登录默认跳转」与测试基面——偏离本表早前「dashboard 系统插件」的设想，属执行期偏差已记录 |
| **业务插件** | cms（已有），后续按需 |

归属原则：**「被消费的基建在核心，管理界面在插件」**（素材库、settings 同此逻辑）。

## 3. 扩展点体系（M6 主体）

### 3.1 Widget（仪表盘扩展点，Q3-A 定案）
- 插件提供 `database/widgets.php`（key/title/permission/sort）+ `admin/views/widgets/<key>.vue` 卡片组件。
- 前端 `import.meta.glob` 动态渲染（与菜单机制同构），权限过滤复用现有机制，数据加载由卡片组件自行调用插件 API。
- 仪表盘页 = 壳：按权限渲染所有启用插件贡献的 widget；`dashboard` 系统插件即该壳的宿主。
- 首批消费者：op-logs（今日登录/操作数卡片）。

### 3.2 Settings（设置归属模型，round3-Q3 定案）
- `settings` 表（§5.4 已规划）：`key(unique), value(jsonb), addon_key` —— **addon_key 即所有权**。
- **隔离规则**：插件可配置**自己的** setting（读写限 `addon_key = 自己`）；**系统 setting（addon_key=system）共用**：所有插件可读、不可写；**不可修改其他插件或系统的 setting**。
- 核心提供 `Setting` 存取服务（归属校验在此收口）+ 内部 HTTP API；settings 系统插件提供 schema 声明（`database/settings.php`：key/label/type/默认值/归属）与管理页（按声明渲染表单）。

### 3.3 事件目录（埋点 = harness 契约，round3-Q2 定案）
- 已有：`admin.login.successed`、`attachment.saved`、`attachment.deleted`。
- **新增：API 中间件对写方法（POST/PUT/DELETE）自动派发 `AdminOperationLogged`**（路由/脱敏参数/结果码/耗时/IP）；登录**失败**也记。参数脱敏用遮蔽表（password/token 类字段）。
- op-logs 插件只监听存储与查询；保留策略默认 90 天、可配，清理挂在插件自身。
- 事件清单属框架公开契约，文档化于本规格；删改视为破坏性变更。

## 4. 机制完整化（M7）

1. **插件管理 HTTP 界面 + 接口**：列表/安装/卸载/启停/详情（权限 `system.addon.*`），替代 CLI 的人工操作。
2. **`upgrade()` 钩子落地**：检测已装版本 < 磁盘版本 → 跑插件 upgrade(fromVersion) → 更新注册表（当前无调用方）。
3. **依赖拓扑解析**：安装/启用的依赖检查从「存在」升级为「启用且无环」（拓扑排序）。
4. **明确不做**：zip 打包导入导出（自用无分发场景，目录结构已预留）；素材库插件化（backlog，等第二个消费方）。

## 5. 路线图

| 里程碑 | 内容 | 形态 |
|---|---|---|
| **M6 扩展点 + 系统插件** | widget 机制（§3.1）、settings 基建 + 归属隔离 + schema（§3.2）、op-log 埋点中间件 + op-logs 插件（§3.3）、仪表盘壳改造、三系统插件入库 | 计划→实现→评审→验收 |
| **M7 机制完整化** | 插件管理界面、upgrade 钩子、依赖拓扑（§4.1–4.3） | 同上 |
| **M8 正确性打磨（C）** | 全面审计：边界用例、权限粒度、事务与并发 | 一轮评审+修复 |
| **M9 交互打磨（B）** | 批量操作、筛选器、表单体验、空态/骨架屏 | 待形态细化 |
| **M10 视觉（A）** | 设计系统/主题 | 待形态细化 |

## 6. 边界备忘

- 系统插件**无特权标记**：允许卸载（机制单一），卸载后相关菜单消失，重装恢复；文档标注「随仓库捆绑」。
- 本规格冻结后，M6 计划中的实现细节（widget schema 字段、脱敏遮蔽表、schema 类型集）按既有约定（信封/权限串/表前缀/测试隔离）在计划内定案，不再上会。
